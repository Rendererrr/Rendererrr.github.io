# ESP model preview

`simple_base/ui/esp_model_preview.h` provides `ui::EspModelPreview`. It is an optional host canvas; registering it does not change game entity acquisition, feature IDs, the ESP renderer, or existing product previews. The shared implementation lives in `src/esp` so canonical, independent V2 and combined builds compile the same code.

Load a validated TFMP0002 or L4DMP001 mesh with `setModel(bytes, materials)`. Each `PreviewMaterial` supplies owned RGBA32 enemy/friendly textures. Geometry uses Y up. Meshes are centered and normalized for preview projection. The loader bounds counts and rejects invalid sizes, indices, bone parents and nonfinite values transactionally. An invalid replacement leaves the previous model usable. `renderPreviewModel` expects a successfully decoded mesh and returns transparent pixels, projected bounds and anatomical bone segments.

Call `draw(registry, hotkeys, friendly, name, health, distance, size)` inside the host's normal ImGui window. The last three sample values describe the preview only. Health uses a synthetic maximum of 100 and distance uses the standalone scene's world-unit label (`u`); they never replace actual game telemetry. A separate canvas draws the canonical `drawEsp` pipeline, including box fill/gradients, all four text/bar positions, independent health text, colors, range, teammate policy and snaplines relative to the canvas. ESP changes are immediate without rerasterizing the model. The preview measures the full, unclipped ESP geometry and fits it together with the model inside an eight-pixel canvas margin; this includes outlined text, four-side bars and snaplines. Larger labels may scale the composition down, without changing saved feature text sizes. Auto canvas height is bounded by the visible page space. The additive `drawEsp(..., clipToViewport)` overload supports this measurement; the original overload retains viewport clipping for game rendering.

The model uses a depth buffer and perspective-correct textured sampling. The image is cached until model, relationship, size or pose changes. Drag rotates, the wheel zooms in 0.025 steps within 0.90x–1.10x, and double-click restores the default view. The slider and restored camera values use the same limits. Hosts can also use `pose`, `setPose`, `reset` and the returned `EspStats`. One instance belongs to one canvas/context. Use normal ImGui per-instance IDs around hosts with multiple canvases.

The ImGui renderer must support `RendererHasTextures`. Managed texture pixels survive renderer-device recreation. Resized textures retire after outstanding frames; context shutdown owns final cleanup. Shut down the renderer backend before destroying the ImGui context. Route the containing draw list through the same Capture Protection surface as the menu.

The combined standalone preview demonstrates registration through `Application::setEspPreview`. Its Scout and Soldier assets are embedded only in the preview executable, never every game UI library. Source/asset hashes are recorded in `../UI-vboth/docs/MODEL_PREVIEW_ASSETS.json`. No running TF2 game, extraction tool or another project's build directory is needed by the finished preview.

## Validation

The `model_preview` CTest runs decoding failures, depth/triangle-order independence, relationship textures, canonical ESP toggles/range, cache reuse, actual drag/wheel/double-click input and deferred texture retirement. It also verifies both zoom clamps, orbit extremes, uncut long-name glyphs, large stacked labels/bars on each side, complete geometry containment and short parent windows. Run the complete canonical and combined x64/Win32 suites after shared changes. Native combined acceptance and independent per-edition state are covered by `../UI-vboth/tools/test-model-preview.ps1 -Architecture x64` and `x86`. Inspect the generated normal, settings, narrow and protected-surface PNGs. These synthetic checks do not establish game behavior, external-recorder exclusion or foreground performance.

## Host profile metadata (2026-10-09)

`draw` accepts an optional final `const ui::EspPreviewSubject &subject` argument. Its defaults preserve existing callers: prefix `esp.`, player kind, enemy/friendly relationship selected by the existing boolean, and distance units `u`. Hosts may supply a different feature prefix, `EntityKind`, an explicit `EntityRelationship`, and a distance-unit string such as `m`. The canonical renderer receives these values directly, so picking IDs and category colors match the selected host profile. The metadata string views need remain valid only during the synchronous draw call.

MTA uses this contract for its Players/NPCs/Vehicles/Self CJ sample; its baked assets are embedded only in the MTA consumer scope. Preview activation overrides belong to a copied registry and must not enable live game features. Keep canvas IDs distinct across target/profile contexts. Existing calls and their texture, input, range and reset behavior remain covered by `model_preview`; MTA adds profile-ID, isolation and original-CJ asset checks in its own tests. Rebuild static consumers after this signature change. Record architecture-specific acceptance in the consumer's validation guide; synthetic tests do not establish gameplay acceptance.
